# VITE UI

## Necessary UseEffects (keep as-is)
- `client/src/App.jsx` – `useEffect(..., [])` (App startup) (Necessary). The initial data load + workspace initialization must run exactly once; this ref guard keeps the async work from re-triggering during StrictMode or re-renders without introducing new hooks.
- `client/src/App.jsx` – `useEffect(..., [pageLocked])` (Necessary). Browser `beforeunload` can only be wired from an effect, so this listener is the only practical way to block navigation while `pageLocked` is true.
- `client/src/hooks/useTitleIconAnimation.js` – spinner effect (Necessary). Managing the interval for `document.title` requires an effect; moving it elsewhere would scatter lifecycle logic or leave intervals running.
- `client/src/hooks/useWebSocketProgress.ts` – websocket connection effect (Necessary). The shared manager must react to `taskId` changes, so keeping `setIsConnected`/`setProgress` inside an effect is the cleanest place to start/stop the socket and ping interval.
- `client/src/hooks/useKeyboardShortcuts.ts` – global `keydown` listener (Necessary). Shortcuts must tap into the document, so registering the listener from an effect is standard practice and keeps teardown predictable.

## Opportunities for Improvement
- `client/src/App.jsx` – `useEffect(() => setCanvasRefreshKey(0), [currentImage])` currently resets the key every time even when it already equals `0`, forcing needless renders and preventing manual refresh adjustments. Reset only when the key drifted or consider delegating the refresh key logic to the component that actually increments it.
- `client/src/App.jsx` – `useEffect(..., [loading, pendingRestart, composerPrompt])` flips `pendingRestart` to `false` and triggers `generateImage()` whenever the flags align. This can loop if `generateImage` mutates `pendingRestart`/`loading`. A dedicated restart command or reducer would keep the transitions deterministic.
- `client/src/components/PromptComposer/PromptComposer.tsx` – `useEffect(..., [initialData, setNodes])` rewrites the node store and uses `setTimeout` to reset the guard flag. Rapid workspace swaps race with user edits. Consider a promise/ref-based guard or a reducer that only applies incoming data if the trigger hasn't already been cleared.
- `client/src/components/PromptComposer/PromptComposer.tsx` – `useEffect(..., [nodes.length, setNodes, initialData])` forces the default tag whenever the list empties, making "empty" states impossible and causing repeated renders. Derive the fallback node in render or guard the setter so it only runs when the list truly lacks nodes.
- `client/src/components/TimelineItem.jsx` – metadata fetch runs without cancellation. Navigating between cards quickly lets stale metadata overwrite newer items or mutate unmounted components. Track the latest request ID or cancel the fetch before applying dimensions.
- `client/src/components/InpaintCanvas/components/CanvasArea.jsx` – the brush indicator effect (`setShowBrushIndicator`) rewrites the boolean every time the dependencies flip, even if the result is unchanged, causing unnecessary renders. Only call the setter when the calculated value differs from the current state.
- `client/src/components/InpaintCanvas/components/CanvasArea.jsx` – the Alt+wheel handler (`setBrushSize`) adds/removes a DOM listener on each render, which can fire during teardown. Attach it once (empty dependency array) and memoize the handler so it doesn't re-register.
- `client/src/components/InpaintCanvas/hooks/useDrawing.tsx` – the `inputImage` effect resizes canvases and appends mask history without aborting. Rapid swaps can flood the history with stale data. Guard updates with an image-version ref or copy the previous mask before resizing.
- `client/src/components/UpscaleDialog.jsx` – `useEffect(..., [selectedUpscaler])` mirrors the prop into local state on every render, overriding user changes whenever the parent re-renders. Sync only when the dialog opens or when the prop truly changes from the current selection.
- `client/src/components/UpscaleDialog.jsx` – `useEffect(..., [availableUpscalers])` reloads `lastUpscaler` from `localStorage` whenever new options arrive, which can flip the selection mid-workflow. Limit this to the initial mount or guard it by checking whether the stored value already matches the current choice.
- `client/src/components/UpscaleDialog.jsx` – the image-load effect attaches a listener but doesn't cancel it when `sourceImage` changes fast, so outdated handlers still set `imageDimensions`. Track the current source with a ref and only update the state for the active image.
- `client/src/components/Sidebar.jsx` – the canvas-dimension effect adds a `load` handler and mutates `canvasDimensions` even when the same image reloads or disappears. Debounce the setter, compare the dimensions before updating, or skip the effect when no image exists.
- `client/src/components/InpaintCanvas/hooks/useDrawing.tsx` – both border-related effects rerun whenever the callback/history change, which happens often during drawing. Stabilize `updateBorderVisualization` (e.g., via `useCallback`) so the effects do not spin unnecessarily.
- `client/src/components/InpaintCanvas/components/CanvasArea.jsx` – the cursor-tracking effect never cancels pending `requestAnimationFrame` handles and keeps listeners attached even when the indicator isn't visible. Cancel the animation and only register listeners when needed.
- `client/src/components/NumberSelector.jsx` – the wheel handler mutates `value` on every scroll even if the clamped result doesn't change, resulting in duplicate renders. Early return when the value stays the same and memoize the handler to avoid reattaching the listener every render.
- `client/src/components/WorkspaceBrowser.jsx` – `loadStructure()` fetches data and immediately sets state without checking if the modal is still mounted. Close the modal before the response returns and the effect will still mutate state, triggering warnings. Track a mounted flag or cancel the fetch.
- `client/src/components/InpaintCanvas/components/InpaintParametersPanel.jsx` – the padding wheel handler calls `setInpaintFullResPadding` for every scroll event, so passive scrolling changes padding unintentionally. Only mutate padding when the control is focused or `deltaY` passes a larger threshold.
- `client/src/components/ResolutionIndicator.jsx` – the global `mousedown` listener closes the popup on every click, even when it is already closed, causing extra renders and racing with other popups. Guard the setter with `isOpen` and only register the listener while the popup is open.
- `client/src/components/InpaintCanvas/components/StatusBar.jsx` – `useMemoryUsage` polls every 5 seconds and calls `setMemoryUsage` even when the value hasn't changed, which keeps rerendering the status bar. Skip the setter when the measured value equals the previous one.
- `client/src/components/PromptComposer/components/TagComponent.tsx` – `inputValue` sync effect writes the prop into local state even if it hasn't changed. Guard the setter with a comparison (`tag.value !== inputValue`) to avoid redundant renders as you type.
- `client/src/components/OptionPicker.jsx` – dropdown-position effect recomputes `setPosition` whenever the dropdown opens, even when nothing changes, causing extra renders. Compare the computed coordinates before setting or memoize them.
- `client/src/components/OptionPicker.jsx` – global-close effect always calls `setIsOpen(false)` on document clicks, even when the menu is already closed, so every click causes work. Early exit when `isOpen` is false or only register the listener while the menu is open.
- `client/src/components/OptionPicker.jsx` – focus-reset effect forces `setFocusedIndex` whenever `options`/`value` change, which can steal keyboard focus if the parent mutates those props simultaneously. Derive the focused index from `value` instead of forcing state changes.
- `client/src/hooks/useWebSocketProgress.ts` – clearing effect (`setProgress(null)`/`setLivePreview(null)`) fires on every `taskId` change, so rapidly toggling IDs can erase fresh data. Debounce clearing or guard it so it only runs when `taskId` truly becomes `null`.
- `client/src/hooks/useWebSocketProgress.ts` – subscription effect processes every websocket message by calling multiple setters, and bursts can flood React with renders. Batch updates or coalesce similar messages when possible.
- `client/src/components/InpaintCanvas/hooks/useCanvasState.tsx` – auto-fit effect adjusts zoom/pan before the image is ready, leading to repeated `setZoom`/`setPanOffset` calls while waiting for the image load. Wait for `img.complete` or listen for the load event before running the layout logic.
- `client/src/components/InpaintCanvas/hooks/useCanvasState.tsx` – view-mode effect flips `viewMode` between "edit" and "result" as images shuffle, sometimes toggling twice per render. Debounce the effect or check whether the target mode already matches before calling the setter.
- `client/src/components/InpaintCanvas/hooks/useCanvasState.tsx` – preview mask effect hides and shows the mask on every preview frame, so fast live previews make the mask flicker. Consolidate the mask visibility transition and skip redundant toggles.
- `client/src/components/InpaintCanvas/hooks/useCanvasState.tsx` – pointer-lock effect rebuilds listeners whenever `panType` changes, which can fire `setIsPanning`/`setPanType` multiple times inside the cleanup. Throttle the teardown or memoize the handler so listeners persist safely.
- `client/src/components/InpaintCanvas/hooks/useKeyboardShortcuts.tsx` – the shortcut effect rebinds on every brush/softness change, creating duplicate listeners that fight over state setters. Keep the handler stable (via refs) and register it once.
- `client/src/components/PromptComposer/store.ts` – the store subscription triggers `setNodes` even after the component unmounts, producing "setState on unmounted component" warnings. Track the mounted flag in the cleanup and skip setter calls once unmounted.
- `client/src/components/PromptComposer/node-contents/TextNodeContent.tsx` – `useEffect(..., [node.value])` adjusts textarea height on every value change, which can cause layout thrashing during typing. Debounce the adjustment or compare the scrollHeight before updating to avoid unnecessary DOM manipulations.
- `client/src/components/InpaintCanvas/components/InpaintCanvas.jsx` – document-level mouse event listeners (`mousedown`/`mouseup`) are attached on every render when handlers change, potentially causing duplicate event bindings. Memoize the handlers or attach them once with empty dependencies and use refs for dynamic behavior.
- `client/src/components/InpaintCanvas/components/InpaintCanvas.jsx` – wheel event effect attaches/removes listeners whenever the image state changes, which can flicker during live previews. Only register the listener when images are present and debounce the handler to prevent rapid zoom adjustments.
- `client/src/components/NumberSelector.jsx` – wheel handler attaches a listener on every render and processes every scroll event without throttling, causing excessive value updates during smooth scrolling. Throttle the handler or only activate it when the component is focused/hovered.
- `client/src/components/WorkspaceBrowser.jsx` – `loadStructure()` fetches data on mount without cancellation, so closing the modal before the request completes still triggers state updates. Add an AbortController or mounted flag to prevent state mutations after unmounting.
- `client/src/components/InpaintCanvas/components/InpaintParametersPanel.jsx` – wheel handler for padding adjustment processes every scroll event without focus checks, so passive scrolling changes padding unintentionally. Only mutate padding when the control is focused or implement a larger scroll threshold.
- `client/src/components/InpaintCanvas/components/StatusBar.jsx` – `useMemoryUsage` polls memory every 5 seconds and calls `setMemoryUsage` even when unchanged, triggering unnecessary re-renders. Skip the setter when the measured value equals the previous one to reduce render cycles.
